# Admin A1: foundation, auth, shell, plans

Spec: `srahira-backend/docs/specs/2026-10-10-investment-platform-design.md` (Architecture, Admin, Security).

## Goal

A standalone Next 16 admin console that talks to `srahira-backend` only from the server, with staff sign-in (password + TOTP), a role-aware shell and full plan management.

## Stack

- Next 16.3.5, React 19.2.8, Tailwind 4, TypeScript 5, eslint-config-next 16.3.5 (same as `srahira`), Vitest.
- `@nextera/contracts` via `file:../srahira-backend/packages/contracts`, compiled through `transpilePackages`; `turbopack.root` is the parent folder so the linked package resolves.
- No UI kit. Small local components (Button, Field, Badge, Table, PageHeader) on top of tokens adapted from `srahira/src/app/globals.css`.

## Tasks

1. Scaffold: package.json, tsconfig, next.config (security headers, `X-Robots-Tag`), eslint, postcss, vitest, globals.css, root layout with `robots: noindex`, `robots.ts` disallow all, AGENTS.md/CLAUDE.md.
2. Backend client `src/lib/backend/client.ts` (`server-only`): `createBackendClient({ baseUrl, serviceKey, fetch, timeoutMs })` returning `{ ok, status, data } | { ok: false, status, error }`. Sends `x-service-key`, `authorization: Bearer`, `x-forwarded-for`, `x-client-user-agent`, `cache: "no-store"`, aborts on timeout, maps network/timeout/non-envelope failures to `unavailable`/`internal`. `src/lib/backend/server.ts` binds env (`SRAHIRA_BACKEND_URL`, `SRAHIRA_ADMIN_SERVICE_KEY`) and the incoming request's IP/UA. Unit tests with a mocked fetch.
3. Session: cookie `srahira_admin_session` (host-only, httpOnly, Secure, SameSite=Strict, path `/`, expires with the backend session). `getStaff()` wraps `/v1/staff/auth/me` in React `cache`; `requireStaff()` redirects to `/login` without a cookie, to `/login?expired=1` on 401, and to `/account/password` when `mustChangePassword` is true (missing field = false). Server actions re-check through `requireActionStaff(permission)`.
4. `src/proxy.ts`: everything except `/login` and static assets requires the cookie, otherwise redirect to `/login?next=`. `/login?expired=1` clears the cookie. `next` is sanitised to same-origin paths.
5. `/login`: email, password, 6-digit TOTP → `POST /v1/staff/auth/login`; field errors from the envelope; `account_locked` and `rate_limited` messages use `retryAfterSeconds`. Logout action calls `POST /v1/staff/auth/logout` and clears the cookie.
6. Permissions: `can(role, permission)` in `src/lib/permissions.ts` mirroring the spec roles table; nav sections defined in `src/lib/nav.ts` with `available` flags, filtered by role. Both unit-tested.
7. Shell: `(console)` route group layout with sidebar (Dashboard, Plans now; other sections listed but hidden until built), staff name/role, sign out.
8. Dashboard placeholder with staff and role.
9. Plans: list all statuses with badges; create and edit forms (rupees → `rupeesToPaise`, percent → `percentToBps`); activate/archive via PATCH status; delete drafts. Backend field errors (`rateBps`, `minPaise`, `maxPaise`, ...) mapped back to form fields. Writes gated to owner/ops in UI and actions; support sees read-only.
10. Change password page `/account/password` → `POST /v1/staff/auth/password { currentPassword, newPassword }`, forced when `mustChangePassword`.
11. `.env.example`, README, `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` green.

## Tests

- Backend client: headers, JSON body, bearer, no-store, 204, error envelope, non-JSON error, network failure, timeout.
- Permissions and nav filtering per role.
- Plan form parsing and backend field mapping.
- Safe `next` redirect.

## Revisions (2026-10-12)

- Moved into the Nextera monorepo as `frontend/admin` (`@nextera/admin`), contracts as the `@nextera/contracts` workspace, env vars `NEXTERA_*`.
- Production cookie `__Host-nextera_admin_session`; dev uses the unprefixed name without Secure.
- Data layer is TanStack Query v5: key factory and `queryOptions` in `src/lib/queries`, typed GET Route Handlers under `src/app/api` (`/api/session/me`, `/api/plans`, `/api/plans/[id]`), server prefetch with `HydrationBoundary`, writes through `useMutation` calling server actions and invalidating keys.
- Hosted on Vercel (root directory `frontend/admin`, domain `admin.nextera.srahira.com`); backend on Railway.
